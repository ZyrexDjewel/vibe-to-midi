# Vibe-to-MIDI Microservice Documentation

## 1. Project Overview & Architecture
`vibe-to-midi` is an AI-powered microservice that converts natural language text prompts into downloadable, binary MIDI (`.mid`) audio files. It operates as a 4-step assembly line translating human intent into musical structures.


```

┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│   User Prompt   │ ───>  │     Gemini      │ ───>  │   pretty_midi   │ ───>  │    .mid File    │
│ ("Funky Bass")  │       │ (JSON Output)   │       │ (Binary Sound)  │       │  (Downloadable) │
└─────────────────┘       └─────────────────┘       └─────────────────┘       └─────────────────┘

```

**Core Stack & Components:**
* **Web Layer (`FastAPI` & `Uvicorn`):** Provides the HTTP POST endpoint (`/api/v1/generate`) to accept user prompts and stream back audio files.
* **AI Engine (`google-genai`):** Uses `gemini-3.6-flash` to evaluate prompts and compose musical note properties.
* **Schema Enforcement (`Pydantic`):** Enforces strict type compliance on model outputs to guarantee valid JSON structures.
* **Audio Synthesizer (`pretty_midi`):** Converts numeric note definitions into standard binary MIDI byte arrays.
* **Container & CI (`Docker`, `GitHub Actions`):** Ensures isolated execution and automated test verification.

## 3. Technical Highlight: Schema Enforcement

Standard Large Language Models return unstructured free text, which cannot be parsed directly by deterministic audio libraries. To fix this, `vibe-to-midi` implements **constrained decoding** using Pydantic schemas.

### The Data Contract

Every note generated by Gemini is bound to four core physical properties:

| Field | Type | Description |
| --- | --- | --- |
| `pitch` | Integer | Standard MIDI pitch code (0 to 127). |
| `start_time` | Float | Timestamp when the note activates (seconds). |
| `end_time` | Float | Timestamp when the note releases (seconds). |
| `velocity` | Integer | Strike force / volume parameter (0 to 127). |

### Execution Pipeline

1. **Schema Definition:** `MIDINote` and `SongStructure` Pydantic models define the required structure.
2. **Constrained Generation:** The model call includes `response_schema=SongStructure` inside `GenerateContentConfig`, forcing Gemini to emit pure JSON matching the schema.
3. **Data Hydration:** `SongStructure.model_validate_json(response.text)` parses raw text into validated Python objects before synthesis begins.

## 4. API Reference

### `POST /api/v1/generate`

Generates a custom MIDI sequence based on a descriptive prompt.

* **Request Body:**

```json
{
  "prompt": "Synthwave lead melody at 120 BPM in E minor"
}

```

* **Response (200 OK):** Binary file stream (`audio/midi`) containing `vibe.mid`.
* **Response (422 Unprocessable Entity):** Invalid or missing prompt payload.

## 5. Containerization & CI/CD Pipeline

* **Docker Execution:** Run `docker compose up --build` to launch the API inside an isolated Linux container on port `8000`.
